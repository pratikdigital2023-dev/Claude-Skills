# Client Kickoff

The first 60 minutes of a project either set you up to ship on time or guarantee
scope creep. This skill runs the kickoff meeting that prevents the second.

## When to use

- Contract is signed and deposit is paid
- Before any design or build work starts
- After re-engagement following a long pause

## Pre-kickoff checklist

Send 3 business days before the meeting:
- [ ] Signed SoW + invoice paid (don't kick off without this)
- [ ] List of attendees with roles
- [ ] Pre-read: 1-page project summary
- [ ] Access form for: domain registrar, current host, CMS, GA, GSC,
      Figma, GitHub, Slack, brand assets
- [ ] Discovery questionnaire (if not already done)

## Kickoff agenda (60–90 min)

| Time | Section | Owner |
|---|---|---|
| 0:00 | Intros + roles | Account lead |
| 0:10 | Goals & success metrics | Client |
| 0:20 | Walk through SoW | PM |
| 0:30 | Timeline + critical milestones | PM |
| 0:40 | RACI walkthrough | PM |
| 0:55 | Tools & access | Tech lead |
| 1:05 | Communication cadence | PM |
| 1:15 | Risks + assumptions | All |
| 1:25 | Next steps + first decisions needed | PM |

## RACI matrix template

For each major deliverable list:
- **Responsible** — does the work
- **Accountable** — owns the outcome (one person only)
- **Consulted** — input before decision
- **Informed** — told after decision

Common roles to map:
| Deliverable | Agency PM | Designer | Dev lead | Client lead | Client SME |
|---|---|---|---|---|---|
| Sitemap | A | C | C | R | C |
| Visual design | C | R/A | I | C | I |
| Copy | I | C | I | A | R |
| CMS schema | I | C | R/A | C | C |
| QA sign-off | A | C | R | R | C |
| Go-live | R/A | I | R | C | I |

## Communication cadence (recommended)

- **Weekly status email** — Monday AM: progress, blockers, decisions needed
- **Weekly working session** — 30 min, same time each week
- **Slack/Teams channel** — for async questions, < 24hr response SLA on biz days
- **Milestone reviews** — async via Loom + 30-min call to discuss
- **Decision log** — running doc of every locked decision (date + owner)

## Review SLA (write this into the SoW)

Client commits to:
- Feedback within **3 business days** of any review request
- **One consolidated voice** per round (not 5 stakeholders sending separate emails)
- **Two rounds of revisions** per major deliverable; 3rd round triggers change order

If the client misses an SLA, the timeline shifts day-for-day. Document this
in writing the moment it happens.

## Kickoff deck slides (12 slides)

1. Project name + start/launch dates
2. Why this project exists (their words)
3. Success metrics
4. Audiences + primary actions
5. Sitemap (high-level)
6. Phases + milestones
7. RACI
8. Tools & access checklist
9. Comms cadence
10. Risks + assumptions
11. First decisions needed (with owners + due dates)
12. Q&A

## First decisions needed (week 1)

Always come out of kickoff with:
- [ ] Final sitemap structure approved
- [ ] Brand direction confirmed (existing or evolving)
- [ ] Tech stack confirmed (CMS, host, frameworks)
- [ ] Content delivery plan (who writes what, by when)
- [ ] Three competitor/inspiration sites identified

## Anti-patterns

- Kicking off before deposit is paid
- No identified single decision-maker
- "We'll figure out content later" — block until plan exists
- Skipping the access form to "save time"
- Verbal-only RACI (always write it down)
